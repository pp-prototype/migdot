## 배경과 조사 범위

README, 인계·동기화 문서, React 화면, 저장 훅, 동기화 로직, 보드 배치, CSS, SQL과 기존 테스트를 읽었다. 원본 파일과 MIG DOT의 실행 코드를 수정하지 않았고 소스 복사·의존성 설치·빌드·서버 연결·브라우저 실행은 하지 않았다. MIG DOT에는 이 조사 기록만 추가했다. 실제 환경 변수나 개인 기록은 읽지 않았다.

## 현재 기능

학습 대상 목록에서 보드로 이동하고, 겹쳐진 포스트잇을 선택해 상세를 연다. 학습 대상 생성, 포스트잇 생성·삭제, 검색, 사진 첨부, 대상별 색상 순환과 최대 12장 보드 페이지 전환을 제공한다. 사진은 입력 형식과 용량을 확인한 후 가로 최대 1000px로 축소한다. 사진을 포함한 JSON 내보내기가 있다.

기록 수정, 대상 수정·삭제, 백업 파일 가져오기, 드래그 배치, PWA 및 오프라인 작성 큐는 미구현이다. 인계 문서의 예전 ‘로그인 없음’ 설명 뒤에 동기화 준비 추가 이력이 있으므로 최신 코드와 후속 절을 함께 확인해야 한다.

## 기술과 데이터

React 19, Vite 6, JavaScript, lucide-react 및 Supabase SDK를 사용한다. 별도 자체 API 서버는 소스에서 확인되지 않았다. 로컬 모드는 post-it-learner-v1 키의 localStorage에 학습 대상과 기록 및 이미지 데이터 URL을 저장한다.

Supabase 설정 시 로컬 모드 대신 로그인 기반 계정 데이터를 사용하도록 구현돼 있다. learning_workspaces에 사용자별 JSON 문서와 revision을 저장하고, learning-images 비공개 Storage 버킷을 사용한다. 저장 RPC는 사용자 ID와 revision을 검증하고, 사진은 서명 URL로 조회한다. 다른 기기의 변경은 화면 복귀·온라인 복귀와 30초 주기로 조회한다. 실제 연결·SQL·RLS·기기 간 동기화는 원본 문서상 미검증이며, 이번 조사에서도 서버 상태를 확인하지 않았다.

## 재사용 가치와 통합 시 조정 사항

- 보드 배치·색상 순환의 순수 함수, 저장소 클래스, 동기화 훅과 검증 시나리오는 재사용 가치가 있다. 이번에는 코드로 가져오지 않았다.
- main.jsx에 자체 createRoot, 앱 헤더, 목록·보드·모달이 함께 있어 페이지 컴포넌트 분리와 공통 셸 연결이 필요하다.
- 현재 대상 선택은 React 상태이며 새로고침과 뒤로가기용 URL 라우팅은 없다. 제안 경로는 /post-it-learner 및 /post-it-learner/topics/:topicId이며 미확정이다.
- 전역 CSS의 body, main, footer, 버튼과 .app, .brand, .site-header, .intro 등의 규칙이 MIG DOT와 충돌할 수 있다. CSS Modules 또는 모듈 범위 스타일로 격리한다.
- /images/*.svg 절대 경로는 모듈별 에셋 경로로 정리한다.
- 모듈 내부 코르크 보드와 포스트잇 시각 언어는 유지하고 외부 탐색·홈 이동은 MIG DOT 공통 셸을 따른다.
- TypeScript 프로젝트에 맞춰 데이터 모델부터 타입을 정의한다. 기존 핵심 동작을 유지하면서 단위별로 변환하는 방법을 제안한다.
- 모듈에서 Supabase 클라이언트와 로그인 UI를 별도로 중복 생성하지 않도록 공통 인증 연동이 필요하다. MIG DOT의 공통 인증은 아직 미구현이다.

## 기존 데이터 이전의 핵심 제약

localStorage는 origin(프로토콜·호스트·포트)에 종속되므로 기존 앱과 MIG DOT의 주소가 다르면 같은 저장 키라도 기존 기록을 직접 읽을 수 없다. 기존 ‘이 브라우저 기록 가져오기’도 현재 origin의 저장소만 읽는다. 원본 JSON 내보내기를 활용하되, MIG DOT에서 데이터 검증·충돌 처리·복원 가능한 가져오기를 구현하는 경로를 검토해야 한다. 현재는 내보내기만 있고 파일 가져오기는 없다.

클라우드 데이터를 쓰고 있다면 프로젝트·사용자 ID·사진 경로와 권한 대응을 따로 조사한다. 이번에는 실제 데이터 유무를 확인하지 않았다. 운영 데이터를 자동 이전하거나 원본 서비스를 종료하지 않는다.

## 검증 결과

기존 board-layout 및 sync-core 테스트를 읽기 전용 명령으로 실행해 총 9건 통과했다. 테스트는 순수 함수와 저장소 모형을 사용하므로 실제 인증·RLS·사진 저장·브라우저 UX의 검증 결과로 해석하지 않는다.

## 제안 및 후속 작업

첫 이식 후보로 적합하다. 보드 경험과 기록 기능을 유지하면서 컴포넌트·라우팅·스타일을 MIG DOT에 맞게 나누는 방향을 제안한다. 이식 전에 보존할 기능 범위, 수정 기능과 백업 가져오기의 완료 조건 포함 여부, 실제 기존 데이터와 공통 인증 도입 순서를 결정한다. 지금은 조사만 완료했으며 이식은 승인·실행하지 않았다.
