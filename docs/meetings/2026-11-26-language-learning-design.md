# 어학 모듈 설계 및 기능 가설

- 논의일 2026-11-26 (Asia/Seoul)
- 상태 설계 검토 초안

## 배경과 목표

공부하다 만난 단어를 빠르게 담고, 내가 본 문장을 연결해, 다음 방문에서 기억을 확인한다. 우선 검증할 흐름은 **수집 → 예문 연결 → 복습 → 다음 방문에서 이어하기**다.

## 시스템 설계 제안

공통 셸의 보호 모듈로 지연 로딩하고 오류 경계를 사용한다. 공통 로그인·모듈 권한·Supabase를 재사용한다. 어학 기록과 복습 로직은 새 모듈이 소유한다. 모든 사용자 데이터에 소유권과 모듈 이용 권한을 함께 검증하는 RLS를 적용한다. 다른 계정의 단어와 예문을 연결할 수 없도록 DB 제약도 둔다.

- **단어** — 학습 언어, 원문, 선택 입력인 뜻. 단어만 저장하면 미정리로 표시하고, 뜻을 추가하면 단어 카드 복습이 가능해진다.
- **예문과 연결** — 예문 원문과 선택 입력인 번역·출처를 한 번 저장한다. 연결에는 단어와 예문에서 실제 가릴 표현을 기록한다. 활용형을 직접 지정할 수 있고, 예문을 수정해 가릴 위치가 없어지면 다시 지정하도록 표시한다.
- **복습 기록** — 단어 뜻과 예문 빈칸의 결과를 각각 남긴다. 답을 열 때는 기록을 바꾸지 않고 ‘다시’ 또는 ‘기억함’을 누를 때 결과와 다음 복습일을 함께 저장한다. 응답 재전송으로 결과가 중복되지 않게 한다. 세션을 닫았다 열면 저장된 결과 기준으로 이어간다.
- **일괄 입력** — 언어를 한 번 지정하고 줄마다 단어, 또는 탭으로 구분된 단어와 뜻을 입력한다. 저장 전 신규·중복·형식 오류를 확인한다. 중복은 기본으로 건너뛰고 같은 표기의 다른 뜻을 별도 항목으로 둘지는 보류한다. 저장 실패 시 원문을 유지한다.

## 화면 설계와 논의할 선택지

공통 내비게이션 아래에 어학 모듈의 로고와 이름을 두고, 상단 탭으로 ‘복습’과 ‘단어장’을 오간다. 단어 상세에서 뜻과 연결된 예문을 함께 보고 문장을 추가한다. 모바일은 한 열, 넓은 화면의 단어장은 목록과 상세를 나란히 보는 구성을 제안한다. 기존 앱과 여백·조작 규칙을 맞추고, 복습 화면은 큰 학습 텍스트와 한 번에 한 문제에 집중한다.

- **첫 화면** — 복습할 분량과 ‘복습 시작’을 보여주는 안과, ‘단어 추가’와 최근 단어를 먼저 보여주는 안이 있다. 초안은 복습할 항목이 있는 재방문에는 복습을, 빈 계정에는 첫 단어 추가를 우선한다.
- **문제 방식** — 답 펼치기와 자기 채점을 먼저 검토한다. 객관식은 고르는 부담이 낮고, 타이핑은 철자 확인에 적합하다. 첫 버전에서 어느 쪽이 필요한지는 실제로 공부하는 단어와 문장으로 결정한다.
- **모바일 조작** — 대표 버튼에 텍스트 라벨을 쓴다. 단어장 검색은 상시 입력창을 후보로 둔다. 보조 도구를 접으면 기존 44×44px 버튼, 펼침 상태와 키보드 초점 규칙을 적용한다. 저장 실패, 긴 문장, 복습 중단 후 재개를 시안에서 비교한다.

## 결정 및 다음 논의

사용자가 구현에 앞서 시스템, 기능 가설, 디자인 논의를 요청했다. 이 문서의 데이터 구조와 화면 구성은 제안이다. 우선 실제로 단어를 가져오는 출처와 복사 형식을 확인하고, 실제 단어와 예문으로 붙여넣기·연결·복습을 검토한다. 자동 뜻·예문 생성, 공유 단어장, 고급 복습 알고리즘은 이후 검토 대상으로 둔다.

## 이름과 첫 구현 결정

앱 이름은 스틸라(Stilla)로 정했다. 잉크 한 방울이 남기는 자국으로, 자신이 만난 말을 고르고 기록해 여러 번 돌아보는 학습을 표현한다. 종이색 배경과 먹빛 글자, 청록색 대표 버튼을 사용한다. 첫 방문에는 단어 담기를, 복습할 카드가 있으면 최대 5장 복습하기를 우선한다.

입력은 여러 줄과 탭으로 구분한 뜻을 지원한다. 복습은 답을 입력하거나 마음속으로 떠올린 뒤 스스로 채점하는 방식을 채택했다. 초기에는 개인 작업공간 한 행으로 단어, 예문 연결, 복습 이력과 진행 위치를 함께 저장한다. 계정별 접근 정책과 버전 비교를 적용한다.
