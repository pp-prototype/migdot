# 포스트잇 러너 저장 및 사용 흐름 설계

- 논의일 2026-11-18 (Asia/Seoul)
- 상태 개인별 기록 관리와 이관 제외 확정 · 세일러는 후속 구상

## 배경과 목적

현재 MIG DOT의 포스트잇 러너는 고정 예시로 주제 목록, 겹친 보드, 검색, 상세 조회를 제공한다. 저장 기능은 없다. 공통 Google 로그인과 모듈 접근 권한이 구현됐으므로 개인 기록에 이를 적용하고, 모바일에서도 빠르게 적고 다시 찾는 흐름을 설계한다.

## 사용자 경험 제안

학습 대상 → 기록 목록 → 상세·수정 흐름과 기존 주제 URL을 유지한다. 모바일은 한 열 목록, 데스크톱은 겹침 없는 카드 그리드를 기본으로 한다. 포스트잇 색은 보조 요소로 쓰고 제목과 태그는 항상 읽을 수 있도록 한다. 기록이 없는 주제에는 첫 기록을 추가하는 버튼을 표시한다. 검색 결과가 없을 때는 검색어를 지울 수 있게 한다.

주제 안에 ‘새 포스트잇’을 두고 주제를 미리 지정한다. 제목과 내용으로 기록을 만들고 태그는 선택으로 둔다. 검색은 주제 안의 제목·내용·태그를 대상으로 하고 최신 작성 순으로 보여준다. 저장이 실패하면 편집 내용을 유지하고 다시 시도할 수 있게 한다. 같은 기록이 다른 기기에서 바뀌면 서버 내용과 작성 중 내용을 확인할 수 있게 한다.

## 데이터베이스와 적용 순서 제안

1. 기존 Supabase 프로젝트에 주제와 기록 테이블을 추가한다. 두 테이블에 소유자를 두고 복합 외래키로 다른 사용자 주제에 기록을 연결할 수 없게 한다. RLS는 현재 모듈 이용 권한과 행 소유권을 함께 확인한다. 기록별 버전으로 동시 수정 충돌을 감지한다.
2. 개인 주제와 텍스트 기록을 생성·수정하고, 검색·조회 및 기록 삭제를 제공한다. 삭제는 확인을 거친다. 주제 일괄 삭제는 복구 정책을 정한 뒤 추가한다. 서버 오류, 로그인 만료, 빈 계정은 각각 안내한다.
3. 이관할 기존 기록이 없으므로 사용자는 빈 학습 공간에서 시작한다. 운영 전 백업과 별도 환경 복원을 확인한다. 사진 첨부는 비공개 Storage와 파일 정리 흐름이 준비되면 검토한다.

## 개인 기록과 세일러

로그인하고 모듈 이용 권한이 있는 사용자는 각자의 학습 주제와 포스트잇을 생성하고 관리한다. 기록은 기본 비공개이며 운영자 권한도 개인 기록 열람을 허용하지 않는다.

후속 세일러 탭에서는 작성자가 직접 공개한 기록을 다른 사람이 탐색할 수 있게 한다. 첫 공개 단위로 포스트잇 한 장을 제안한다. 주제에 새로 추가하는 기록과 첨부 파일은 별도의 공개 선택을 거친다. 공개 전에 다른 사용자에게 표시될 제목·본문·태그·작성자 표시명을 미리 보여주고, 공개를 취소하면 세일러 조회와 공개 상세 경로에서 함께 제외한다.

세일러 조회에는 공개가 승인된 필드만 제공하는 별도 경계를 둔다. 개인 기록의 소유자 정책과 편집 권한은 유지한다. 첫 버전에는 공개 스키마를 추가하지 않는다. 세일러 접근 범위, 작성자 표시명과 공개 기록의 갱신 방식은 후속 논의에서 결정한다.

## 보류와 검증

겹친 코르크 보드의 보조 보기, 실시간 갱신, 오프라인 저장은 실제 사용 필요를 확인한 뒤 검토한다. 초기에는 화면 복귀 시 다시 조회한다. 개발 중 두 계정의 데이터 분리, 모듈 권한 회수, 다른 소유자의 주제 참조 차단, 두 기기의 동시 편집을 확인한다. 모바일과 데스크톱에서 첫 기록 생성, 검색, 뒤로가기, 키보드 포커스, 저장 실패와 재시도를 검증한다.

현재 코르크 보드를 별도로 사용할 필요가 있는지는 화면 설계 단계에서 확인한다. 운영 Supabase의 적용 상태는 구현 단계에서 확인한다.
