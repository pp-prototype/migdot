## 1. 사용자가 얻는 가치

오늘 끝낼 과업과 할수록 좋은 루틴을 구분해, 할 일을 바로 등록하고 집중 후 명시적으로 완료하며 지난 실행을 돌아보는 개인용 실행 관리 앱이다. 게임 테마보다 ‘오늘 무엇을 끝내야 하는가, 지금 무엇에 집중하는가, 어떤 실천이 쌓였는가’가 서비스의 중심이다.

## 3. 기획과 실제 구현의 구별

초기 기획서는 후속 목표도 담고 있으므로 그대로 현재 기능 목록으로 쓰지 않는다.

- 현재 타이머는 고정 25분이다. 자동 휴식 5분, 사용자 지정 시간, 여러 뽀모도로 사이클은 구현된 것으로 확인되지 않았다.
- 저장하는 session은 현재 세션 하나다. 과업별 여러 집중 세션 이력이나 일별 누적 집중 시간 분석은 현재 모델에서 제공하지 않는다.
- 루틴 추가·당일 체크·조회는 있으나 이름 수정·보관·요일별 반복은 없다.
- 과업 등록·완료/취소·지난 과업 이동은 있으나 제목 수정·삭제·세부 메모 편집 화면은 확인되지 않았다.
- 최근 28일 수행 수는 제공하지만 연속일/달성률 분석 전체가 구현된 것은 아니다.
- 과거 루틴 체크는 조회용이다. 실천 셀은 날짜 선택 동작이며 과거 수행을 수정하지 않는다.
- 오늘로 이동은 현재 코드에서 과업의 date 필드를 변경한다. 이전 날짜 미완료 목록에서는 빠지며 원래 예정일과 이동 이력을 따로 보존하지 않는다.
- Google OAuth 실설정·다른 실제 기기·HTTPS 아이폰 설치는 문서상 후속 검증이다. 스크린샷 및 테스트 파일 존재가 실서비스 검증 완료를 의미하지 않는다.

## 4. 사용자 흐름과 개선 후보

권장 흐름은 오늘 → 빠른 추가 → 바로 완료 또는 집중 → 기록 확인이다. 이 흐름은 유지할 가치가 있다.

현재 ‘루틴 기록’ 화면은 루틴 관리, 잔디와 날짜별 과업 이력까지 담아 목적이 혼합된다. 통합본에서는 오늘, 루틴, 집중, 기록의 역할을 명확히 나누는 것을 제안하되 메뉴 개수와 배치는 시안에서 결정한다.

진행 중 다른 과업의 집중 버튼은 현재 집중으로 안내한다. 집중 대상이 바뀌지 않는다는 점을 사용자가 쉽게 이해하도록 버튼과 상태를 표시해야 한다. 상태 기반 탭은 URL 기반으로 바꾸어 새로고침·뒤로가기·직접 진입을 지원한다.

## 5. 디자인 분석

기존 docs/previews의 오늘·집중·기록 모바일 이미지를 확인했다. 이는 저장된 예시 스크린샷이며 현재 작업 트리의 새 실행 화면을 확인한 것은 아니다.

### 활용할 원리

- 필수 과업을 위에, 선택 루틴을 아래에 두는 정보 위계
- 완료/전체 수와 진행 막대를 함께 보여주는 상태 표현
- 한 목록 패널의 구분선으로 과업을 정리하는 방식
- 입력 부담이 적은 추가 다이얼로그
- 집중 화면에서 대상 과업·큰 시간·주요 조작에 집중하는 구성
- 수행 셀을 실패가 아닌 기록 없음으로 설명하는 비강압적 습관 표현
- 색 외에 라벨·아이콘·텍스트로 상태를 구분하는 방식

### MIG DOT 기준으로 조정할 부분

MIG DOT의 공통 글자·색상 역할·카드·버튼·접근성이 우선한다. 검정/핏빛/금색, 픽셀 글꼴과 처형인 캐릭터는 선택 가능한 표현 자료이며 유지 의무가 없다. 빨강을 일반 실행 버튼에 반복하면 오류/삭제 의미와 충돌할 수 있으므로 역할을 재배정한다. ‘집행·귀환’ 문구는 ‘과업·완료·오늘의 목표’처럼 이해하기 쉬운 표현을 기본 후보로 둔다.

어두운 테마가 원칙상 무조건 금지되는 것은 아니지만 접근성·일관성과 유지보수의 근거가 있어야 한다. 기존 게임 UI가 전역 body와 공통 컴포넌트를 덮어쓰도록 가져오지 않는다.

현재 원본의 하단 명령 바를 그대로 붙이면 MIG DOT의 모바일 하단 네 메뉴와 중첩된다. 공통 메뉴를 유지하고 모듈 탐색은 본문 상단의 보조 탐색 또는 경로별 화면으로 구성하는 방향을 제안한다. 집중 표시나 추가 버튼도 공통 하단 메뉴와 겹치지 않게 한다.

## 6. 통합 서비스 구조의 차이

현재는 React + Node API + SQLite + 자체 Google OAuth + IndexedDB 저장/전송 대기열을 묶은 구조다. 기존 클라우드가 Supabase라는 가정으로 진행하면 안 된다.

MIG DOT는 단일 Supabase와 공통 인증·인가를 기준으로 하므로 Node 서버, 자체 쿠키/CSRF/OAuth, 전체 문서 저장·충돌 화면과 로컬 우선 저장은 기본 이식 대상에서 제외한다. 다만 소유권 검증, 중복 요청 방지, 저장 확인, 실패 후 재시도, 미전송 데이터 보호에 관한 테스트 관점은 재사용한다. 인증 방식이 달라지므로 기존 보안 장치를 단순 제거하는 것으로 접근 제어가 완성되는 것은 아니다.

제안 데이터 경계는 실행 모듈의 routines, routine_records, tasks, focus_sessions다. 실제 테이블명은 추후 결정한다. 모든 행에 공통 사용자 소유권을 적용하고 루틴+날짜의 수행 기록 유일성, 하위 기록/집중과 부모 항목의 소유자 일치, 기록 단위 동시성 및 활성 집중 하나의 제약을 서버에서 검증한다.

집중 기능은 뷰를 벗어나도 계속되는 기대가 있다. 페이지 컴포넌트의 1초 타이머 자체를 공유하지 않고 종료 시각과 상태를 기반으로 복원한다. 모듈 간 이동 후 작은 집중 상태 표시를 공통 셸에 둘지, 여러 기기에서 집중 세션을 어떻게 이어갈지는 후속 결정이다. 종료 알림/푸시는 별개이며 보장하지 않는다.

## 7. PWA와 오프라인

원본 manifest의 시작 주소와 서비스 워커 범위가 루트 기준이다. 그대로 가져오면 MIG DOT 전체의 정적 캐시·설치 정체성과 충돌할 수 있다. PWA는 플랫폼 전체의 단일 정책으로 검토한다.

클라우드를 단일 원본으로 삼는 것과 제한된 오프라인 캐시는 개념상 양립할 수 있으나, 현재 원본의 로컬 우선·게스트 작성·계정 캐시·자동 전송 대기열은 아직 승인되지 않은 별도 운영 정책이다. 초기 이식에서는 제외하고 필요 시 캐시 접근·계정 전환·암호화/삭제·충돌·실패·실기기 검증까지 포함해 결정한다.
