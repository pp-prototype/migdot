# 2026-11-17 개인용 서비스의 배포와 보호 범위

- 일시: 2026-11-17 (Asia/Seoul)
- 배경: 사용자는 향후 Vercel 배포를 원하며 개인용 도구에 로그인·보안이 어느 정도 필요한지 고민함
- 상태: 논의 중 · 배포와 인증 설정 변경 없음

## 검토

개인용 여부는 대상 사용자의 수를 말하고, 인터넷 접근 가능 여부와 기록의 공개 여부는 별도다. 예시·공개 가능한 문서만 있는 체험 단계는 앱 로그인을 미룰 수 있다. 실제 개인 기록을 Supabase에 저장하는 단계에는 읽기뿐 아니라 변경·삭제 권한도 제한해야 한다.

개인 사용에는 공개 회원가입, 여러 로그인 공급자와 복잡한 역할 체계가 필요하지 않다. 승인된 본인 계정 한 개와 공통 로그인·소유권 RLS·비공개 사진 저장을 기본 후보로 제안한다. 로그인 편의성과 세션 유지 범위는 구현 전에 결정한다.

Vercel은 2026-09-09 공식 변경 안내에서 모든 플랜에 추가 비용 없이 Production을 포함한 All Deployments Vercel Authentication을 제공한다고 발표했다. 이전 Standard Protection 자료와 범위가 다를 수 있으므로 배포 시 프로젝트의 실제 보호 범위를 확인한다. Vercel 계정으로 입구를 잠그는 방식은 개인용 사이트와 번들 문서 접근을 제한하는 대안이다.

Vercel 배포 보호는 Supabase의 독립 API에 사용자 인증을 전달하거나 DB RLS를 대체하지 않는다. 브라우저가 Supabase에 직접 접근하는 현재 예정 구조에서는 데이터를 보호하는 인증·인가가 별도로 필요하다. 앱 화면을 공개하고 데이터만 비공개로 할지, 사이트 입구도 제한할지는 선택이다. 두 번의 로그인 단계를 무조건 기본값으로 제안하지 않는다.

## 다음 결정

Vercel은 사용자의 희망 배포 대상이며 이번 논의에서 배포하지 않는다. 개발원칙서의 현재 배포 기술 표는 변경하지 않았다. 개인 기록 사용 전 공통 인증과 데이터 정책을 구현하고, 문서 공개 범위를 정한다. 현 단계에 더 큰 보안 체계를 추가하는 작업은 하지 않는다.
