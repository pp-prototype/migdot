# 2026-11-17 공유와 모듈별 접근 권한 검토

- 일시: 2026-11-17 (Asia/Seoul)
- 사용자 의도: 향후 지인/다른 사용자와 공간을 공유하되 특정 라우트 진입 제한을 고려
- 상태: 권한 구조 제안 · 공개 범위/초대 방식 미확정
- 작업 범위: 분석 기록만. 코드·인증·DB·배포 변경 없음

## 권한 경계

공통 로그인, 모듈 이용 권한, 개별 데이터 열람·변경 권한을 구분한다. 모듈 사용을 허용해도 운영자의 개인 데이터가 공유되는 것은 아니다. 기본은 사용자별 개인 데이터 분리이며 공동 보드/프로젝트 공유는 별도 기능으로 다룬다.

라우트 가드는 메뉴/카드를 필터링하고 직접 URL 진입도 제한해 UX를 제공한다. 데이터 보호는 DB의 RLS 및 Storage·RPC/서버 정책에서 적용한다. 프런트엔드 검사만으로 API 요청과 배포된 JS·정적 문서 원본을 보호할 수 없다.

## 초기 설계 제안

- 공통 로그인은 한 번만 수행한다.
- 모듈 등록은 고정 경로 자체보다 안정적인 module_id에 접근 정책을 연결한다.
- 공개 화면, 로그인 사용자용, 지정 사용자용의 세 접근 범주를 둘 수 있다. 실제 공개 화면은 배포 전 결정한다.
- 지정 사용자용 모듈은 관리자 관리 사용자-모듈 허용 정보로 제어한다. 권한 레코드가 없거나 조회 실패/로드 중이면 보호 화면과 개인 데이터를 표시하지 않는다.
- 초기 권한은 owner와 일반 사용자 구분 및 모듈 사용 허용 여부로 제한한다. 기능별 세부 역할·조직/워크스페이스는 필요할 때 추가한다.
- 권한 부여/회수는 승인된 관리자 경로로만 수행하고 사용자에게 자기 권한 변경을 허용하지 않는다. 단순 owner UI 표시가 DB 관리자 권한을 의미하지 않는다.
- 운영 데이터 정책은 현재 모듈 이용 가능 여부 AND 행 소유권을 검증한다. 모듈 내부 읽기 전용/편집 역할이 필요해지면 명시적으로 확장한다.
- 권한 회수 후에도 직접 API로 접근하지 못하도록 DB 현재 권한을 검증하는 방식을 기본 후보로 둔다. 오래된 JWT 클레임·프런트 상태만 신뢰하지 않는다.

## 예시

본인은 학습·실행·회의록 등 운영 대상 모듈을 사용한다. 지인 A에게 학습 모듈만 허용하고 지인 B에게 실행 모듈만 허용할 수 있다. 둘 다 자기 기록만 접근하며 본인 데이터는 보이지 않는다. 문서의 일부를 공개할지는 별도 결정한다. 경로와 권한 예시는 실제 정책 확정이 아니다.

## 정적 자산과 공유 데이터

SPA의 코드와 번들 Markdown은 배포 자산이다. 로그인한 사용자에게 특정 화면을 숨겼다는 이유로 해당 모듈 코드나 문서 원문도 비공개라고 설명하지 않는다. 비밀 정보는 번들에 넣지 않는다. 특정 지인에게만 문서 본문을 공개하려면 권한 확인 후 서버/Storage에서 제공하는 방식이나 별도의 배포 접근 제한이 필요하다.

같은 모듈을 쓰는 것과 동일 보드를 함께 편집하는 것은 다르다. 후자는 리소스별 공유 대상과 읽기/쓰기 권한을 별도로 설계해야 한다.

## 검증 후보

권한 없는 카드 숨김, 직접 URL 차단, 미인증 리디렉션, 로딩/오류 중 개인 화면 비노출, 다른 사용자와 미승인 사용자 API 거부, 소유자 위조 거부, 권한 회수 후 재조회/저장 차단, 사진 접근 제한을 검증한다. 권한 회수는 이미 내려받은 데이터나 기존 서명 URL을 소급 회수하지는 못하므로 화면 캐시와 파일 URL 수명도 별도 고려한다.
