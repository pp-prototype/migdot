# 허브 디자인 방향 검토

- 논의일 2026-11-16 (Asia/Seoul)
- 상태 사용자 화면 반영 요청으로 구현 진행 · 기록은 AI 작성 초안
- 주제 국내 다사용 서비스의 디자인 특성과 MIG DOT 적용 방향

## 배경과 목적

사용자는 허브의 전체 스타일을 정하기 위해 국내에서 사용량이 많은 웹·앱 서비스의 디자인 공통점 분석을 요청했다. 최초 조사 이후 사용자가 화면 반영을 요청하여 제안 방향으로 UI를 구현했다.

## 조사 범위와 한계

사용량의 근거는 모바일인덱스의 2026년 상반기 TOP100 및 2026년 10월 데이터 기반 11월 보고서를 참고했다. 이용자 수가 디자인의 우수성이나 인과관계를 입증하지는 않는다. 공식 디자인 시스템과 서비스 안내를 함께 검토했으며 로그인한 모든 앱 화면을 직접 실측한 조사는 아니다. 아래 적용 수치는 MIG DOT를 위한 제안이다.

## 주요 검토 사항

- 토스: 사용자가 얻는 가치와 쉬운 의사결정을 앞세우는 공식 원칙, 역할에 따라 색을 관리하는 디자인 시스템을 참고한다.
- 네이버: 여러 서비스로 이동하는 허브 구조와 관심사별 정보 구획을 참고한다.
- 당근: 컴포넌트·인터랙션·스타일의 공통 기준과 제목·본문의 역할 구분을 참고한다.
- 카카오톡: 즐겨찾기와 목록 가독성 개선에서 반복 사용 경로의 중요성을 참고한다.
- 흰색·중립색 기반, 글자 위계, 제한된 강조색, 반복되는 탐색 규칙을 적용 후보로 삼는다. 이 공통점은 자료를 바탕으로 한 디자인 해석이며 모든 화면에 동일하게 적용된다는 뜻은 아니다.

## 제안 방향

차분하고 친숙한 개인용 앱 허브를 제안한다. 앱 진입을 주된 과제로 두고 개발 기록 접근을 함께 제공한다.

- 기존 `/`, `/meetings`, `/updates`, `/documentations` 경로 유지
- 짧은 MIG DOT 헤더, 모든 페이지에서 일관된 네 개 메뉴
- 메인은 개인용 앱 목록을 중심으로 구성하고 회의록·업데이트·문서는 보조 바로가기로 구분
- 실제 앱이 없는 현재는 정직한 빈 상태 표시. 미구현 앱의 사용 가능 상태나 가짜 사용 기록은 표시하지 않음
- 문서 메타데이터가 준비되면 실제 최신 기록을 메인 하단에 제공하는 방안 검토
- 밝은 회색 바탕, 흰색 표면, 짙은 본문, 기존 녹색을 제한된 강조색으로 사용
- 제목 28~32px, 본문 16px, 보조 정보 14px, 카드 모서리 16px를 초기 시안 값으로 제안
- 데스크톱은 앱 카드 그리드, 모바일은 간결한 목록과 네 개 메뉴의 하단 탐색 구성을 검토
- 문서 화면은 목록과 본문, 모바일에서는 문서 선택을 접을 수 있는 구성을 검토

## 보류 및 후속 작업

사용자의 화면 반영 요청을 근거로 밝은 배경, 녹색 강조, 앱 영역과 기록 구분, 모바일 하단 메뉴 및 문서 목록 접기를 적용했다. 앱별 아이콘·강조색, 모바일 하단 메뉴, 최신 기록 노출 범위는 시안에서 구체화한다. 실제 앱 이식 전 즐겨찾기·최근 사용·통합 검색은 필요성을 확인한 뒤 도입한다.
