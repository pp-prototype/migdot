# 공통 Google 로그인과 모듈 접근 권한

- 변경일: 2026-11-17 (Asia/Seoul)
- 앱 버전: v0.1.0 유지 · 커밋 전 작업
- 대상: 공통 세션·라우팅·홈·운영자 화면·Supabase SQL·검증

## 변경 사항

Google PKCE 로그인과 콜백, 원래 경로 복귀 및 외부 리디렉션 차단을 추가했다. SDK의 흐름 ID를 유지하고 React Strict Mode에서 코드를 중복 교환하지 않는다. 공통 세션은 서버의 사용자 식별과 DB 권한 응답을 확인하며 조회 오류·계정 불일치는 차단한다.

허용 모듈만 홈/메뉴/최근 기록에 표시하고 직접 URL 접근도 보호한다. `/settings/access`는 실제 owner만 열며, 승인·모듈 허용/회수는 서버 RPC에서 다시 확인한다. 로그아웃·계정 변경·권한 회수 시 보호 화면을 해제한다. 주기/포커스/온라인 복귀 재확인을 추가했다.

`app_modules`, `app_members`, `app_module_grants`, 접근 조회/운영자 RPC와 RLS 마이그레이션을 추가했다. 첫 운영자는 자동 생성하지 않는다. 권한 테이블의 클라이언트 쓰기와 일반 사용자의 자기 승격을 차단한다. 향후 업무 테이블에 모듈 권한과 소유권을 함께 적용할 helper를 제공한다.

설정 없는 개발 환경의 예시 체험과 실제 인증 모드를 구분한다. 배포 빌드는 설정이 없으면 닫힌 상태다. Vercel SPA 경로 fallback을 준비했으나 배포하지 않았다. PGlite는 SQL 테스트용 개발 의존성이며 클라이언트에 포함하지 않는다.

## 영향과 제약

인증 설정 후에는 기존 다섯 모듈 모두 기본 제한된다. 승인만 받은 회원은 모듈 허용을 별도로 받아야 한다. 모듈의 현재 예시/메모리 데이터는 유지하며 운영 데이터 저장·사진 권한은 아직 연결하지 않았다. 정적 문서 본문은 빌드에 포함되어 원문 비공개를 보장하지 않는다.

실제 Supabase·Google 연결 정보가 없어 원격 SQL 적용과 실계정 검증은 수행하지 않았다. 추가 입력은 프로젝트 URL과 공개 키이며, OAuth 비밀값은 관리 콘솔에 설정한다.

## 검증

린트·타입 검사·빌드와 PostgreSQL 엔진(PGlite) 기반 RLS 테스트를 통과했다. 브라우저 전체 22개 중 21개가 통과했고, SDK 기본 설정에서 선택적인 흐름 ID를 필수로 가정했던 테스트를 수정한 뒤 해당 1개를 재실행해 통과했다. 로그인·권한 관리의 데스크톱/모바일 화면도 확인했다. 브라우저 인증 응답은 테스트용 가짜 API이며 실제 Google OAuth·원격 SQL 적용은 아직 검증하지 않았다.
