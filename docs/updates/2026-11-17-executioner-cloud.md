- 변경일 2026-11-17 (Asia/Seoul)
- 대상 실행 트래커, Supabase 개인 기록, 검증, 문서
- 기록 커밋 `87f8c08`

## 변경 사항

로그인 사용자는 빈 개인 집행록에서 시작하고 과업·루틴·회고를 서버에 저장한다. 미완료는 원래 계획을 유지한 채 오늘 목록으로 이어진다. 최초 계획 후 경과와 현재 일정 경과, 직접 일정 조정 횟수를 구분한다. 미래 일정·보류·취소를 지원하며 루틴은 이월하지 않는다.

하루 마감과 재열기, 날짜별 회고 수정, 과거 당일 결과와 이후 완료 표시를 추가했다. 과거 결과는 이벤트 시점의 상태로 계산한다. 저장 확인 후 캐릭터가 반응하며 충돌·응답 유실에서는 입력을 유지하고 최신 기록 확인을 요구한다.

## 기술과 적용 조건

`202611170002_executioner_workspace.sql`에 사용자 소유 테이블·RLS·읽기/쓰기 RPC를 추가했다. 클라이언트 직접 쓰기를 금지하고 모듈 권한과 소유권을 확인한다. 사용자별 리비전으로 덮어쓰기를 차단하며 요청 ID로 중복 처리를 막는다. 기존 공통 인증 SQL을 다시 실행할 필요는 없다.

설정 없는 개발 체험은 유지한다. 브라우저 테스트용 체험 서버를 5177로 분리해 실제 `.env`를 읽는 5175 개발 서버와 혼동하지 않게 했다. 인증 테스트는 5176에서 외부 Auth 응답만 대체하고, 새 클라우드 기능 테스트는 실제 마이그레이션을 실행한 PGlite SQL 함수에 연결한다. 원격 Google·Supabase 검증과는 구분한다.

## 검증과 알려진 제약

린트·타입 검사·빌드를 통과했다. 전체 브라우저 25개 테스트를 통과했고, 최종 입력 잠금·날짜별 계산 보완 후 새 클라우드 테스트 3개를 다시 통과했다. SQL 보안 테스트에서 비로그인·미승인·권한 회수 차단, 운영자를 포함한 사용자별 데이터 분리, 직접 쓰기 금지, 오래된 리비전 거절, 중복 요청 무시, 최초 계획·이벤트 보존, 마감 재열기와 루틴 보관을 확인했다. 데스크톱과 320/390px 모바일 가로 넘침을 확인하고 화면 캡처를 저장했다.

초기 전체 검증에서 실제 빌드가 테스트용 배포 빌드를 덮어쓰는 문제가 발생해 테스트 출력도 별도로 분리했다. 원격 SQL 적용·실계정 두 사용자 데이터 분리와 두 기기 검증은 아직 수행하지 않았다. 과업 취소는 영구 삭제가 아니며 오프라인 저장·타이머·알림·기존 데이터 이관은 포함하지 않는다.
