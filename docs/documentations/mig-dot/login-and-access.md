# 로그인과 모듈 이용 권한

## 사용 흐름

실제 Supabase 연결이 설정된 환경에서는 상단 ‘로그인’ 또는 보호된 앱 주소에서 Google 로그인을 시작합니다. 로그인이 완료되면 원래 요청한 화면으로 돌아옵니다. 가입과 서비스 이용 승인은 별개입니다.

승인 대기 중에는 홈과 제한 화면에 사용자 ID가 표시됩니다. 운영자에게 이 ID를 알려주고 승인 후 ‘권한 다시 확인’을 누르세요. 로그인 성공만으로 모듈 권한이나 운영자 권한을 얻지 않습니다.

홈에는 허용된 앱·문서 메뉴와 접근 가능한 최근 기록만 표시합니다. 권한이 없는 주소로 직접 이동해도 해당 모듈을 표시하지 않습니다. 모듈 사용 권한은 다른 사용자의 개인 데이터 공유 권한을 의미하지 않습니다.

## 운영자 관리

운영자는 상단 ‘권한 관리’에서 로그인한 사용자를 승인하고 모듈별 허용을 선택합니다. 서버 확인 후 체크 상태를 반영합니다. 승인을 취소하면 모듈 권한도 제거되며 재승인 후에는 다시 선택해야 합니다.

운영자는 최초에 프로젝트 관리자가 직접 지정해야 하며, 첫 가입자를 자동으로 운영자로 만들지 않습니다. 앱에서 운영자 역할을 부여·제거하는 기능과 초대 이메일 발송 기능은 제공하지 않습니다. 최근 생성된 계정 최대 100개를 표시합니다.

## 로그아웃과 권한 변경

헤더의 로그아웃은 현재 브라우저의 세션을 종료하고 보호 화면을 해제합니다. 다른 기기의 세션을 모두 종료하는 기능은 아닙니다. 이미 발급된 접근 토큰·서명 파일 URL이나 다운로드된 자료가 소급 무효화된다고 가정하지 않습니다.

권한은 화면 복귀·온라인 복귀와 보이는 화면에서 30초마다 재확인합니다. 최초 확인·계정 변경·조회 오류에는 보호 화면을 표시하지 않습니다. 백그라운드 재확인 중 기존 승인 화면은 유지할 수 있지만, 실제 DB 권한 확인은 각 요청에서 별도로 이루어집니다. 접속 오류는 우회 허용하지 않고 재확인 안내를 표시합니다.

## 설정과 현재 제약

원격 Supabase 및 Google 로그인 설정은 별도로 필요합니다. 설정 안내는 저장소 `supabase/README.md`에 있습니다. 원격 API 연결·Google 로그인 시작과 비로그인 API 차단을 확인했으며, 사용자가 실계정 로그인 완료를 확인했습니다. 다른 계정의 승인·권한 분리는 실제 계정으로 추가 확인해야 합니다.

설정이 전혀 없는 개발 서버는 예시 확인용 로컬 체험이며 실제 로그인이 아닙니다. 배포 빌드는 이 체험 권한을 사용하지 않고, 설정이 없으면 보호 모듈을 차단합니다. 부분/잘못된 설정도 체험으로 전환하지 않습니다.

두 기능 앱의 운영 데이터 저장은 아직 연결하지 않았습니다. Markdown 문서는 빌드에 포함되므로 메뉴와 화면 접근을 제한해도 정적 원문까지 비공개가 되는 것은 아닙니다. 비공개 문서 제공은 별도 저장·배포 방식이 필요합니다.

## 앱에서 승인 업무 처리

운영자는 메인의 ‘사용자 승인과 모듈 관리’ 카드 또는 상단 ‘권한 관리’로 진입합니다. 로그인한 계정은 별도 ID 전달 없이 목록에 표시됩니다. 전체·승인 대기/중지·승인됨 필터와 이메일/ID 검색으로 계정을 찾고, 이용 승인 후 허용할 모듈을 선택합니다.

조회된 계정 수와 승인 대기/중지 수는 최근 100개 목록 기준이며, 신규 대기와 승인 취소 계정을 합산합니다. 화면을 보는 동안 30초마다, 화면 포커스 복귀 시 목록을 갱신합니다.
