# 메타 월렛 개발·디자인 원칙

메타 월렛은 사용자가 오늘 쓸 돈을 확인하고, 기억나는 만큼 지출을 남기고, 그 기록을 다음 계획에 활용하도록 돕는다. 사용자가 금액과 일정을 판단할 수 있도록 계산 근거와 선택의 영향을 설명한다.

## 디자인 원칙

홈의 주요 위치는 첫 방문부터 반복 사용까지 유지한다. 입력한 정보와 쌓인 기록에 따라 같은 영역에 다음 행동을 제공한다.

| 영역 | 첫 방문 | 반복 사용 |
|---|---|---|
| 오늘의 지갑 | 진한 배경 카드에 오늘 생활비의 ‘계산 전’ 상태와 잔액 입력을 표시한다. | 오늘 생활비를 가장 크게 보여주고 현재 잔액과 확인 시점을 함께 표시한다. 오늘 기록한 지출에는 별도 라벨을 붙인다. |
| 오늘 쓴 돈 | 카드 바로 아래에서 금액이나 메모 하나로 기록을 시작할 수 있게 한다. | 같은 자리에서 오늘의 기록을 확인하고 수정할 수 있게 한다. 기록을 쉬었던 날이 있어도 오늘부터 다시 시작한다. |
| 다음 일정 | 입금 또는 납부 일정을 추가할 수 있게 한다. | 가까운 일정과 부족 예상 날짜·금액을 보여준다. 부족 내역에서 해당 날짜의 돈 계획을 열 수 있게 한다. |
| 최근 7일 지출 | 첫 기록 이후 홈에 표시한다. | 금액, 메모, 기록한 날짜 수를 보여준다. 반복 패턴을 뒷받침하는 기록이 충분하면 ‘이번 주 돌아보기’를 제공한다. |

- **설정은 필요할 때 이어간다.** 잔액을 입력한 뒤 다음 입금일을 묻는다. 날짜를 모르면 생활해야 할 일수로 정할 수 있다. 사용자는 중간에 설정을 멈추고 일기를 쓸 수 있다. 생활비에는 ‘입력한 일정 기준’이라는 범위와 계산 근거를 표시한다.
- **기록의 정밀도를 드러낸다.** 대략 입력한 금액에는 ‘약’을 붙인다. 메모만 있는 날, 0원을 확인한 날, 기록이 없는 날을 화면과 집계에서 각각 구분한다.
- **돌아보기는 근거와 행동을 연결한다.** 확인할 수 있는 관찰 하나와 근거가 된 날짜·메모를 보여준다. ‘다음 주에 비용 잡기’에서 이름이 입력된 예약 초안을 열고 날짜와 금액은 사용자가 정한다. 변경 전후의 생활비와 부족액을 확인한 뒤 적용한다.
- **다시 비교할 자리를 마련한다.** 잡아둔 비용을 해당 날짜의 일기와 함께 보여주고, 일기가 비어 있으면 기록 여부를 표시한다. 하루 총액을 특정 항목의 실제 지출로 해석하지 않는다.
- **부족은 해결할 날짜와 금액으로 설명한다.** 배정 초과나 기록 누락을 사용자 평가로 바꾸지 않는다. 강조색에는 날짜, 금액, 상태 라벨을 함께 사용한다.

## 개발 원칙

- **확인 잔액, 생활비 계획, 일기에 서로 다른 역할을 부여한다.** 잔액에는 확인 시점을 저장한다. 일기는 날짜별 금액과 추정 여부, 메모를 저장하며 확인 잔액을 변경하지 않는다. 실제 거래 연동을 추가할 때는 이미 확인 잔액에 반영된 소비를 다시 차감하지 않도록 대조 규칙을 둔다.
- **예정 입출금을 날짜순으로 계산한다.** 월급은 입금일에, 상환·고정비·특수비·저축·예약한 생활비는 예정 출금일에 반영한다. 다음 입금 뒤에 큰 지출이 있는 경우도 계산 범위에 포함해 앞서 확보해야 할 금액을 드러낸다. 날짜별 예상 잔액과 최초 부족 날짜·금액을 같은 계산에서 얻는다. 홈, 돈 계획, 변경 미리 보기는 이 계산을 공유한다.
- **카드 소비일과 납부일을 구분한다.** 카드 소비가 실제 거래로 추가되면 소비일의 지출 추이와 납부일의 현금 흐름에 각각 반영한다. 날짜가 지난 미처리 상환·고정비·특수비는 오늘의 현금 흐름에 포함한다. 입출금 처리를 확인할 때는 처리 후 확인한 잔액을 받고 해당 일정을 예상 출금 또는 입금에서 제외한다.
- **비교에 쓰인 데이터의 범위를 보존한다.** 기록일 수, 금액이 있는 날짜 수, 추정 여부를 함께 집계한다. 현재 돌아보기는 반복 키워드와 해당 날짜의 하루 총액에 근거한다. 하루 총액에서 개별 비용을 산출할 수 없으므로 참고값으로 표시하고 예약액은 사용자가 입력한다. 일정 추가·수정·삭제 및 처리 확인 시 변경 전후의 날짜와 금액, 하루 생활비를 이력에 보존한다.
- **내 지갑과 예시 지갑을 구분한다.** 현재 사용자 테스트 버전은 내 지갑의 잔액·일정·일기를 현재 브라우저에 저장한다. 예시 지갑은 돌아보기와 예약을 바로 체험할 수 있도록 따로 제공하며, 그 변경은 내 지갑에 반영하지 않는다. 카드 거래 연결, 자동 납부 확인과 기기 간 동기화는 후속 구현 범위다.

## 돈 계획의 계좌와 지출

- 일반 부채·카드·대출은 남은 부채와 다음 납부일·납부액을 구분한다. 저축 계좌는 현재 저축액과 목표액, 다음 납입 계획을 구분한다.
- 연결한 납부나 저축 일정은 예정 입출금 한 건으로 반영한다. 계좌에서 일정을 수정하면 같은 일정을 갱신한다. 납부나 납입을 확인한 뒤에는 계좌의 남은 부채 또는 저축액을 직접 갱신한다.
- 생활비에는 고정비와 필수 지출을 예정일 기준으로 반영한다. 확인 잔액에는 바로 쓸 수 있는 돈을 입력하고, 부채 총액과 저축 계좌 잔액은 별도로 표시한다. 다음 일정은 한 건씩 등록한다.

## 사용성 검증

- 처음 온 사용자가 설명 없이 금액이나 메모 하나를 남기고 홈에서 확인할 수 있는지 본다.
- 입금일을 모르는 사용자가 기간을 일수로 정하고, 오늘 생활비와 현재 잔액의 의미를 각각 설명할 수 있는지 본다.
- 월급·카드 납부·저축·특수비가 있는 예시에서 부족 날짜를 찾고, 저축이나 비용 예약을 바꿀 때의 영향을 적용 전에 확인할 수 있는지 본다.
- 돌아보기에서 근거 기록을 찾고, 어떤 이유로 다음 계획을 바꿨는지 사용자 자신의 말로 설명할 수 있는지 본다.
- 모바일에서 앱 목록 진입, 일기 저장·재접속, 계획 반영, 예시 지갑에서 내 지갑으로 복귀하는 흐름을 확인한다.
